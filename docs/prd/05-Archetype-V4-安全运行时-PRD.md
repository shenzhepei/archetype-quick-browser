## 1. 产品目标

V4 将 V3 的单进程静态浏览器原型推进为具有真实进程隔离边界、基础会话能力和更实用布局支持的开发者预览版。首要目标不是扩大网站兼容数量，而是确保网页解析与渲染故障不能带崩桌面 UI，并为后续 JavaScript 和公开 SDK 建立可验证的安全边界。

V4 仍不作为通用浏览器公开发行。所有新增能力必须经过版本化命令/事件边界，不允许把 DOM、Renderer 内存或具体 UI 框架类型暴露给桌面壳。

## 2. 用户与场景

- 引擎开发者需要独立重启 Renderer、注入故障并检查资源限制。
- 桌面应用开发者需要 Cookie、基础表单和会话恢复来验证常见静态及服务端页面流程。
- 页面作者需要基础 Flexbox 和公开支持矩阵来判断页面能否稳定呈现。
- 后续 SDK/Runtime 开发需要从参考浏览器中提取已经被生产调用和自动化验证的协议类型。

## 3. V4 必须交付

### 3.1 稳定边界与进程隔离

- 提取框架无关、可序列化且不暴露第三方复杂类型的页面 ID、导航 ID、命令和事件值对象。
- 桌面 UI 与 Renderer Runtime 通过版本化协议通信；协议具备握手、能力协商、请求 ID、长度限制和结构化错误。
- Renderer 进程退出、超时或协议违规时，桌面 UI 保持存活并显示可恢复错误状态。
- macOS Renderer 默认无任意文件访问、无直接网络访问，并受进程级 CPU、内存和消息队列限制。

### 3.2 基础 Web 会话

- 提供按 profile 隔离的 Cookie 存储，至少支持域、路径、Secure、HttpOnly、SameSite 和过期时间。
- 支持文本、密码、复选框、单选框、选择框和按钮的基础表单交互，以及 GET/POST 提交。
- 会话数据与日志不得记录密码、完整 Cookie 值或表单正文。
- 站点权限默认拒绝；V4 不新增摄像头、麦克风、定位或通知能力。

### 3.3 布局与可用性

- 实现常用单行与多行 Flexbox：方向、换行、主轴/交叉轴对齐、`gap`、增长与收缩。
- 发布机器可读的 HTML/CSS 支持矩阵，并为每项支持能力绑定金样或单元测试。
- 标签页可进入休眠状态并从版本化元数据恢复；恢复失败仅影响对应标签页。

### 3.4 诊断与发布基线

- Renderer 生命周期、握手失败、资源超限和恢复结果写入本地结构化日志。
- GitHub Release 产出未签名开发构建和校验和；签名、公证与自动更新仍作为后续发布门槛。
- 保持双语 README、依赖许可证、覆盖率、截图回归和 parser/protocol fuzz 闸门。

## 4. 验收标准

| 维度 | 验收标准 |
|------|----------|
| 边界 | 公共命令/事件类型不依赖 GPUI，序列化 round-trip 和未知可选字段测试通过 |
| 隔离 | 强制终止 Renderer 100 次，UI 进程不退出，页面均进入可重试失败状态 |
| 协议 | 畸形、超长、乱序和版本不兼容消息被拒绝，protocol fuzz 无未解决崩溃 |
| 沙箱 | 自动化探针证明 Renderer 不能直接打开任意用户文件或建立外部网络连接 |
| 会话 | Cookie 域/路径/SameSite/过期规则和基础 GET/POST 表单金样全部通过 |
| 布局 | 新增至少 20 个 Flexbox 金样，固定截图差异不超过 0.5% |
| 恢复 | 休眠及 Renderer 崩溃后，标签页 URL、标题、滚动元数据和历史 100% 恢复 |
| 质量 | 全工作区格式、Clippy、测试、覆盖率、许可证清单及 HTML/CSS/协议 fuzz 通过 |

CPU、内存、恢复延迟和 IPC 吞吐在 V4 建立跨版本基线；除明确资源上限外，不与 Chrome 做比例承诺。

## 5. 明确不进入 V4

- JavaScript 引擎、DOM mutation、Service Worker 和 WebAssembly。
- 完整 HTML 表单规范、文件上传、支付、自动填充和密码管理器。
- Grid、复杂定位、动画、完整媒体查询和 GPU 合成。
- Windows/Linux 沙箱、移动平台和站点隔离多 Renderer 策略。
- 面向公众的签名发行、自动更新和稳定公开 SDK 兼容承诺。
- 扩展系统、云同步、Chromium 兼容舱和本地 AI。

## 6. 实施顺序

| 阶段 | 交付 | 退出条件 |
|------|------|----------|
| A 稳定类型 | `archetype-types` 与现有 Session/BrowserCore 真实调用 | V3 行为不变，ID 无第三方公共类型 |
| B 协议原型 | 版本握手、长度前缀消息、内存 transport、fuzz | 兼容与超限测试通过 |
| C 独立 Runtime | 子进程启动、导航、DisplayList 返回、断连恢复 | kill-loop UI 存活 |
| D macOS 沙箱 | 文件/网络 broker、资源限制、签名继承 | 沙箱探针通过 |
| E 会话与布局 | Cookie、基础表单、Flexbox、休眠恢复 | 对应金样与迁移测试通过 |
| F 开发者发布 | 构建产物、校验和、支持矩阵和验收报告 | V4 全部验收项通过 |

阶段必须按顺序满足退出条件。阶段 A/B 不承诺公开 SDK 稳定性；只有真实边界经过 Runtime 使用后，才进入 04 规范定义的合作方 SDK 实施。

## 7. 发布条件

V4 只有在隔离、协议、沙箱、会话、布局、恢复和质量验收均有自动化证据，且已知限制与第三方许可证同步后才能标记完成。不得用“独立进程”替代沙箱验收，也不得为兼容单个网站绕过同源、TLS 或资源限制。
